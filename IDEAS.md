# Ideas

Improvement ideas for the app, from the idea panel (`/brainstorm`), polish reviews (`/polish`), QA (`/qa`) and you.

## How to use this (Mikkel)

1. Run **/brainstorm** for new feature ideas, or **/polish** to tidy up what already exists (you can add your own notes, e.g. `/polish the stats page feels cluttered`). New ideas appear in the table below with status `proposed`. /polish also fixes small, safe things straight away and only lists the bigger ones here.
2. Read them. Quickest: answer in the terminal. /brainstorm and /polish ask you at the end, and **/ideas** lists everything waiting for you; reply e.g. `approve 1 3, reject 2` and it updates the table for you. Or do it by hand: for each one, change the word in the **Status** column:
   - `proposed` → `approved` if you want it built
   - `proposed` → `rejected` if you don't (it stays here so it isn't suggested again)
3. Save the file and run **/build**. Claude builds every `approved` idea, tests it, runs QA, pushes it and marks it `done`.

You can also add your own idea as a new row with status `approved`. Rows with status `bug` were found by QA; change them to `approved` to get them fixed.

**Design review:** run **/design-review** (optionally with notes, e.g. `/design-review focus on the session screen`). Three strict reviewers score colour, typography and motion from 1 to 10, and you get up to 5 proposals, each with a before/after page (`design-review/<date>/P<n>/compare.html`) to open in your browser. You answer each one in the terminal: **Approve** (built on main straight away), **Reject**, or **Decide later** (it lands here as `proposed`, type `design`; approve it later and /build builds it). The scores and decisions are kept in `DESIGN_SCORES.md`, so you can follow them over time. Five reviewers take part: colour, typography, motion, layout and overall.

**Design loop:** run **/design-loop** (optionally with notes) and leave it running. It works on its own on a separate branch called `design-loop`, so nothing goes live while it runs: each round, five fresh reviewers score the app without knowing the goal, and Claude improves whatever scores lowest, until all five give 9 or more twice in a row (or it stops making progress, or after 8 rounds). Only then does it show you before/after screenshots (`design-review/<date>-final/`) and ask **Approve all**, **Let me pick changes** or **Reject all**; what you approve is merged into the live app. If it stops early it tells you why and asks whether to continue. If it gets cut off, just type /design-loop again and it carries on where it stopped (`DESIGN_LOOP.md`).

Statuses: `proposed` · `approved` · `rejected` · `building` · `done` · `bug`
Type: `feature` (from /brainstorm) · `polish` (from /polish) · `design` (from /design-review) · `bug` (from QA)
Size: **S** = an hour or two · **M** = about a day · **L** = several days
